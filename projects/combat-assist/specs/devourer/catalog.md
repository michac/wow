# Devourer Demon Hunter (Void-Scarred, ranged) — catalog

**Applies to:** Devourer (specID `1480`), hero tree **Void-Scarred**, rotation branch
**ranged** (`!talent.the_hunt`), Midnight 12.1. This is the normative catalog document for
this spec-and-hero pair — the thing a future `Catalogs/Devourer.lua` transcribes.

**One file, three sections.** `../authoring.md` §0 fixes one `catalog.md` per spec
directory; the roster, the fact classification and the state walk are sections here, not
neighbouring documents. (Havoc's three-file split is the standing exception with an owed
consolidation; it is read here for content and rigor, never copied as a layout.)

> **The priority source is `knowledge/classes/demon-hunter/devourer/simc-apl.md`** — the
> Tier-1 simc action priority list for 12.1, generated by `wowkb.simc --kb` from
> `apl_demon_hunter.cpp` at commit `5f916c6` (2026-08-14).

> mechanics prose lives. Every rung number below counts lines **within

## 1. Two provisional premises, dated

Neither is an unexamined default. Both are revisitable and both are recorded as calls.

**1a — Void-Scarred over Annihilator (provisional, 2026-08-17).** The hero-tree call is
**contested**: Icy Veins (2026-08-10) picks Void-Scarred for raid *and* M+; Maxroll
(2026-08-11) has Annihilator "slightly ahead in both"; Annihilator was the Season 1 default
everywhere. Season 2 opened 2026-08-18, so the sims and logs that would settle it did not
exist when this was chosen. `knowledge/classes/demon-hunter/devourer/builds.md` owns the
argument and calls it unsettled. A spec-and-hero pair is the unit cap authors, so an
Annihilator catalog is a **separate document authored later**, never an overlay bolted on
here.

**1b — the ranged branch over the melee branch (fixed for this pass).** `talent.the_hunt`
forks each hero tree in two, and it is a genuine playstyle fork rather than a talent swap.
Measured from the APL:

| Branch | Lines | Distinct presses | Shape |
| --- | ---: | ---: | --- |
| `voidscarred_ranged` | 15 | 13 | a flat priority list — comparable to Havoc's 36 lines / 12 entries |
| `voidscarred_melee` | 3 → `vsm_st` / `vsm_meta` / `vsm_out` | 47 | a **three-state machine** |

The melee branch is not a priority list at all. It branches on single-target / in-Meta /
out-of-Meta and runs a different list in each, presses two buttons nobody else has
(**Reaper's Toll**, **Predator's Wake**), drops **Collapsing Star** outright, and promotes
**Soul Immolation** from last to first. It is a separate rotation and is deferred.

⚠ **Which branch the live guides actually recommend is unresolved.** Icy Veins publishes two
Void-Scarred loadouts as talent strings; nobody has decoded them, so whether they take The
Hunt is unknown. If they take it, this catalog is authored against the branch a Void-Scarred
player does not run. `@verify-ingame` (recorded in `rotation.md`).

## 2. The thirteen presses, and what is not one

`actions.voidscarred_ranged` contains **13 distinct presses** in first-occurrence order:
`voidblade`, `metamorphosis`, `devour`, `consume`, `collapsing_star`, `void_ray`,
`vengeful_retreat`, `reapers_toll`, `pierce_the_veil`, `soul_immolation`, plus
`eradicate` / `cull` / `reap` reached twice through `actions.reaps`.

**Lines that are not a button press, and must never become a row.** A phantom row is worse
than a missing one.

- `variable`, `snapshot_stats` — bookkeeping. `actions.variables` produces **zero** presses;
  read it to understand `wont_drop_meta` / `wont_overcap_cstar`, then classify what those
  *depend on*.
- `call_action_list` / `run_action_list` — control flow. `reaps` is inlined at each call
  site rather than modelled as an entry.
- `pick_up_fragment` — a **movement action**, not a castable. No spell, no cooldown, no CDM
  row. It is real player behaviour and it is the largest thing on this spec no icon can
  carry; it is **not** an entry. (`voidscarred_ranged` is the one branch of four that does
  not contain it, which is part of why it was chosen.)
- `wait,sec=0.05` — an explicit **do nothing**, present in `voidscarred_melee`. Recorded
  because a reading model that always names a press will assert one where the correct
  answer is "hold the global".
- `invoke_external_buff,name=power_infusion` — **someone else's button**.
- `potion`, `use_item,slot=trinket1|trinket2` — consumables and trinket slots, not spells.
  **`actions.cooldowns` produces zero cap rows.** Said once, here.
- `arcane_torrent` — a **racial**, Blood Elves only. Not a spec row.

⚠ **One upstream oddity, flagged and left alone.** `annihilator_ranged` carries
`!set_bonus.midnight_season_2_4pc` where the other three branches carry the term un-negated.
Possibly a typo upstream. It is Tier 1, so it is reported and not "fixed" — and it is
outside this branch anyway.

## 3. The structural finding: the Cooldown Manager does not carry this rotation

This is the most important thing stage 3 turned up and it is not a fact about Secret Values.
It is about which rows exist at all.

cap rides Blizzard's Cooldown Manager, and the set of rows a spec can have is fixed by
`CooldownSetSpell` — the player can hide rows from the pool but cannot add to it. Devourer's
pool is `CooldownSetID 1864` `[T1: CooldownSetSpell @ 12.1.0.69214]`, and its **Essential**
category — the viewer `Anchor.lua` re-orders, and therefore the only row the left-to-right
reading model applies to — contains exactly **six** spells:

| Essential row | Spell | In this branch |
| --- | ---: | --- |
| Reap | `1226019` | yes — overrides to Cull `1245453` / Eradicate `1225826` |
| Voidblade | `1245412` | yes — overrides to Hungering Slash `1239123` / Pierce the Veil `1245483` / Reaper's Toll `1245470` |
| Void Ray | `473728` | yes |
| Void Metamorphosis | `1217605` | yes |
| Soul Immolation | `1241937` | yes |
| The Hunt | `1246167` | **no** — this branch is `!talent.the_hunt` |

So the anchored row is **five icons**. Everything else the branch presses is somewhere else,
or nowhere:

- **Vengeful Retreat** `198793` is in the **Utility** viewer. cap binds it (`Bind.lua` covers
  all four viewers), so it can be skinned and badged — but `Anchor.lua` only re-anchors
  Essential, so it sits outside the ordered scan, the way Havoc's Felblade and Vengeful
  Retreat already do.
- **Consume** `473662` and **Devour** `1217610` are in **no CDM category at all**. Not
  Essential, not Utility, not a tracked buff. Consume is the spec's filler *and*, on the
  Season 2 2-piece, the target of its single largest rank swing (rungs 3–4).
- **Collapsing Star** — the cast (`1221150` / `1221167`) is in no category. Only its
  **stacking counter** aura `1227702` appears, as a **TrackedBuff** row.

⚠ **This is not the same problem Havoc has.** Havoc's Demon's Bite is also absent from its
pool, and Havoc's catalog handles that by binding it anyway and letting the row bind only if
it exists — because Demon's Bite is a *floor* press whose absence costs nothing. Here the
missing buttons include **Collapsing Star at rungs 5 and 9, which outrank Void Ray at rung
8**. When Collapsing Star is the correct press, the five-icon scan will reach **Void Ray**
and stop there. No cue on any existing row can point at a button that has no icon.

⚠ **Blizzard already draws the sealed half, but not somewhere the walk can use.** The same
pool carries `TrackedBuff` rows for exactly the state this spec is made of: **Void
Metamorphosis `1225789`** (which is the *soul bank* aura, not the cast), **Collapsing Star
`1227702`** (the in-window counter), **Moment of Craving `1238488`**, **Eradicate `1226033`**,
**Hungering Slash `1239519`**, **Devourer's Bite `1240201`**, and the **Season 2 2-piece
`1296615`**. cap binds the `BuffIconCooldownViewer`, so this state is reachable and is worth
knowing about — but **re-anchoring a TrackedBuff row into the Essential line was investigated
against the Tier-1 client source and rejected**, and `../render-rationale.md` holds why: a buff
row's swipe means *the aura is up*, the exact inverse of the "swiped == ruled out" term the
elimination model rests on; `wasSetFromCooldown` is always false on a buff row; and with
hide-when-inactive unchecked — a player-facing Edit Mode box — an inactive buff row draws as a
full-colour un-swiped icon, pixel-identical to a ready ability. **Do not re-propose it.**

**The answer is `../render-shelf.md` V12 · Virtual row**, authorised 2026-08-17: a press with
no CDM row draws as a **cap-owned icon in its own panel** — the spell icon at
`tokens.panel.icon_px`, wearing V11's hatch from the same generated `Media/stripes.tga`, and
nothing else. No scan edge, no badge. V12 declares two kinds — **gated** and
**standing** — and §6.1 authors one of each.

## 5. The roster — player problem → fact → treatment

Stage 2's filter: **an ability with no named player problem gets no row.** Eight survive — five
Essential rows, one Utility row, and two **virtual rows** (§6.1). The role tiers are
`../spec.md` §3.1's.

### 5.1 The Essential rows (the scanned line)

- **Void Metamorphosis** (`1217605`, rung 2). *Problem:* it is **not a cooldown** — it is
  fragment-gated, and the icon cannot say *"you need 50 souls"*. The APL's rule has a second
  half too: at 2+ targets, don't transform mid-way through setting up the Eradicate upgrade.
  *Facts:* `ready` (R2) for the tier; `aoe` + `talent(eradicate)` + `proc` (all readable) for
  the hold; the **soul bank** (sealed) for the readout. *Treatment:* **COOLDOWN** + a red
  `blocked` hold (cue **D**) + the sealed bank readout (cue **C**).
- **Reap → Cull / Eradicate** (`1226019`, rungs 6–7). *Problem:* one button wearing three
  faces, and the face changes what it is for — Eradicate is a 25 yd frontal cone you aim, Cull
  is the in-window harvest, Reap is the builder. *Facts:* `ready` (R2), `identity` (R7).
  *Treatment:* **ROTATION** with the identity spine, no cue.
  ⚠ **Its actual APL gate — `action.reap.souls_consumed>=4`, fragments lying on the ground —
  has no API in any lane** (`fact-classification.md` §4.3). The press is directed by readiness alone. Blizzard's own
  glow already says *"upgraded"* (`fact-classification.md` §4.2), which is most of what a hint here would have said.
- **Void Ray** (`473728`, rung 8). *Problem:* it costs **100 Fury**, Fury is secret, and the
  CDM shows it castable when you cannot pay — the exact failure R1 exists for, and this spec's
  only spender with a real cost. It is also the button that *creates* the Eradicate upgrade
  and the Moment of Craving reset, so a dropped channel costs two things the damage number
  does not show. *Fact:* `affordable` (R1). *Treatment:* **ROTATION**, `starved` when
  `insufficientPower` (cue **A**) — Havoc's cue A verbatim.
  ⚠ **Rung 8's hold is not authorable** (`fact-classification.md` §4.2): Eradicate and Moment of Craving share one
  overlay channel, so `proc(reap)` is their OR and the hold needs their AND. Stated as a gap.
- **Soul Immolation** (`1241937`, rung 13). *Problem:* **inside Void Metamorphosis this is not
  a maintenance press — it is the thing that keeps the form alive.** Fury drains continuously
  and accelerating; at zero the window ends; Soul Immolation returns 30 Fury (+12 with *Singed
  Spirit*) over 5 s on a ~1 min cooldown. Spend it early in a window and the save is not there
  when the window is ending. *Facts:* `ready` (R2) — a good proxy for rung 13's
  `active_dot=0` half, since a 5 s effect on a ~60 s cooldown is absent whenever the button is
  up; `identity(transformed)` (R7, readable) for *"am I in Meta"*; secret **Fury** vs an
  authored break point (sealed, S1). *Treatment:* **ROTATION** + a red `blocked` hold (cue
  **B**) while transformed *and* Fury is above one tick of drain.
- **Voidblade → Hungering Slash / Pierce the Veil / Reaper's Toll** (`1245412`; rung 1 outside
  Meta, rungs 11–12 inside). *Problem:* two different problems on one icon. Outside Meta, rung
  1 says *spend the last global before you transform*, because with *Devourer's Bite* Voidblade
  lands a stacking +12 % damage-taken debuff and you want it **on** the window. Inside Meta the
  same row is **Pierce the Veil** (or **Reaper's Toll** while Hungering Slash is the live form)
  — the once-per-window Voidsurge casts. *Facts:* `talent(devourers_bite)` (readable — without
  it rung 1 does not exist); `identity` (R7); the bank at max and the owed Voidsurge are both
  **not readable today**. *Treatment:* **ROTATION**, identity spine, **no cue** — see `scenarios.md` §7's
  documented misordering 2 and §8's ships/waits.

### 5.2 The Utility row

- **Vengeful Retreat** (`198793`, rung 10, **Utility** viewer). *Problem:* in this branch it is
  **not** a mobility press and **not** press-on-cooldown. Its only rung is `buff.voidstep.up` —
  the Hungering-Slash-granted *"your next Vengeful Retreat will release a Cosmic explosion"*.
  No Voidstep, no press, ever. *Fact:* `proc(vengeful_retreat)` (readable, `fact-classification.md` §4.2).
  *Treatment:* **COOLDOWN**, **and no cue** — see §6's *"the cue that was dropped"*.

### 5.3 Named, and deliberately given no row

- **The Hunt / Predator's Wake.** Not in this branch by definition (`!talent.the_hunt`).
- **Reaper's Toll / Pierce the Veil** as *independent* rows. They are the Voidblade row's Meta
  faces, so R7 already draws them; what cannot be drawn is *which one is owed* (`fact-classification.md` §4.2, open).
- **Devour** as an *independent* row. It is Consume's Meta override form on the standing virtual
  row, not a second press — `devour_t : public consume_base_t` shares Consume's cooldown object
  (§6.1). Rungs 14 and 15 are one button.

## 6. The cues, collected

Provisional. Every one is a hypothesis judged by play, exactly as the pilots were.

| Cue | What the player sees | Fact | Tool / channel | Recipe | Sink | Polarity |
| --- | --- | --- | --- | --- | --- | --- |
| **A** starved spender | Void Ray wears `starved` when you cannot pay 100 Fury | `insufficientPower` | emphasis (readable) | R1 | ROTATION emphasis | negative |
| **B** the drain save | Soul Immolation wears `blocked` while you are transformed **and** Fury is above one tick of drain — *don't burn the save early* | secret Fury-% vs an authored `threshold`, gated on `identity(transformed)` | cue (sealed) + readable gate | S1 / V9 | colour curve → badge alpha | negative |
| **C** the soul bank | the bank's count, drawn by the client, anchored beside the Void Metamorphosis row | `void_metamorphosis_stack` stacks (0–50) | **independent context** (sealed) | S2 `player-aura-stacks` / V8 | client-owned count | **none** |
| **D** the Eradicate setup hold | Void Metamorphosis wears `blocked` in AoE mode while *Eradicate* is talented and no Reap-family glow is up | `aoe` + `talent` + `proc`, all readable | cue (readable) | the shipped `aoe` / `talent` predicates + `proc` | corner badge | negative |
| **F** the talent fence | nothing of its own — it **withholds**: cue D where *Eradicate* is untalented, and rung 1 entirely where *Devourer's Bite* is | trait config | gate (readable) | the shipped `talent` predicate | no sink | — |
| **G** target mode | four rungs move on target count; cap asks the player rather than counting enemies | `/cap aoe` | gate (readable) | the shipped `aoe` predicate | — | — |

**This catalog draws no positive cue.** That is a finding, not a budget being respected — the
one-positive rule is explicitly not a budget, and a positive cue here would have been argued on
merits if one had survived. Three candidates were examined and all three resolved another way.

**Cue C is not a cue in the badge vocabulary at all, and that is what dissolves the polarity
question.** The soul bank and the Collapsing Star counter looked like two positive cues in an
earlier draft; they are one recipe — S2 `player-aura-stacks`, one sealed sink, one shape — and
its shipped precedent is **Backdraft**, which `../spec.md` §3.5 describes as *"independent
context… It does not change Conflagrate's tier and does not encode press or hold."* A
client-drawn number has no polarity because it makes no claim about rank. So the merge the
review asked for is right, and it goes one step further: merged, the primitive stops being a
cue and becomes a readout, and the positive/negative axis stops applying to it.

⚠ **And merged, it is instanced ONCE, not twice.** The second candidate — the in-window
`collapsing_star_stacking` counter — is **already drawn by Blizzard twice**: as its own
`TrackedBuff` row (`1227702`, §3) and inside the class resource bar. Its only unserved consumer
is rung 5's single-target `stack>=35` refinement, which has no surface to sit on (V12 says a
virtual row wears the hatch **and nothing else**). It is not authored; `scenarios.md` §7's documented
misordering 1 is the cost, and it is small. The soul-bank instance *is* authored, because it is
the Backdraft move exactly: the number exists elsewhere, and the decision it feeds is made on
the Void Metamorphosis icon.

**The cue that was dropped: Voidstep on Vengeful Retreat.** An earlier draft made this cue
**E**. It is deleted for two independent reasons, either of which is sufficient.

1. **It is not in the row being scanned.** Vengeful Retreat is in the **Utility** category
   (§3) and `Anchor.lua` re-anchors the **Essential** viewer only, so a badge there cannot
   change what an elimination walk reaches. It would be a mark on a surface the reading model
   does not read.
2. **Blizzard already draws it.** Voidstep (`1223157`) is a registered spell-activation overlay
   that icon-highlights Vengeful Retreat (`fact-classification.md` §4.2, Tier 1), and cap deliberately leaves the stock
   proc glow intact (`tokens.surfaces.proc_glow_alpha`). A cap badge would be a second mark for
   a fact the client already marks, on the same icon.

⚠ **The row is still bound, and the reason it was bound no longer exists.** This paragraph used to
say the binding paid for itself because *"the lane border says this is a cooldown-class button in
cap's own vocabulary"*. The shelf's V13 scan edge (2026-08-19) says no such thing — it is one bit,
it carries no class, and it cannot be read as a category by anyone.

What is honestly left is thinner and does not obviously carry the binding:

- **V11's cooldown hatch**, which does say something real (*not now*) and says it without the
  elimination walk having to reach the row. This is the only actual signal the binding buys.
- **Consistent skinning**, which is an aesthetic argument, not an information one.

And reason 1 above cuts against both: Vengeful Retreat is in the **Utility** category, which
`Anchor.lua` does not order and the reading model does not walk — so the scan edge on it is
strictly meaningless, marking membership in a scan that never happens. **This needs an author
decision, not a rewrite**: either bind it for the hatch alone and say so, or unbind it and let
Blizzard's swipe carry the row. It is in `discussion.md`. What it does not get, either way, is a
cue.

### 6.1 The two virtual rows (V12)

`../render-shelf.md` V12 fixes the shape: a cap-owned icon, laid out left to right in
`tokens.panel`, wearing V11's hatch and nothing else. It also fixes **two kinds**, and the kind
is a property of the ability rather than of the moment:

| # | Virtual row | Kind | Serves | Behaviour |
| --- | --- | --- | --- | --- |
| 1 | **Collapsing Star** (`1221167`) | **gated** | rungs 5 / 9 | hatched by default; clears when Collapsing Star is castable **and** `!proc(consume ∪ devour)` |
| 2 | **Consume → Devour** (`473662` → `1217610`) | **standing** | rungs 14–15 | draws **clear, permanently**; asks for no verdict at all |

⚠ **The unknown polarity is inverted from V11** on a *gated* row — on a CDM row an unknown draws
bare because absence of a hatch asserts nothing; on a gated virtual row absence of a hatch **is**
the signal, so **unknown draws hatched**. A standing row has no verdict to be unknown about.

**Consume is standing, and the premise is Tier 1.** `ability-inventory.tsv` gives it **cooldown
`0`**, there is **no `SpellPower` row** for `473662` at `12.1.0.69214` — so no resource cost — and
it has no aura gate and is **castable while moving** `[T1]`. Its availability is a constant, which
is exactly V12's test. It therefore sits at the **right end of the panel**, draws clear at all
times, and carries **no readable gate** — its position encodes its rank, which is what
`../render-shelf.md` Part 0.5 asks for whenever a fact is stable enough to be rank.

⚠ **A standing Consume is not wallpaper, and it is what makes elimination total on this spec.**
Without it there are ordinary states — spender unaffordable, everything else on cooldown — where
every entry on both surfaces is swiped or badged and the correct answer is reachable only from
memory. The standing row is the terminus: the sweep always lands somewhere. `scenarios.md` §7.3's B-3 is that
state.

**Devour is not a second row.** It is Consume's Void Metamorphosis **override form**, resolved by
R7 exactly as Reap → Cull is: `abilities.md` says Consume *"becomes Devour inside Void
Metamorphosis"*, and simc implements `devour_t : public consume_base_t` with
`cooldown = p->cooldown.consume` — **one cooldown object shared by both**, its marker for one
button — and falls Devour's energize back to Consume's. One standing row, two faces. The APL's
rungs 14 and 15 are two lines only because simc models the forms as two actions; in the client
exactly one is castable at a time.

**Nothing is authored for the Soulburst promotion.** The Season 2 2-piece promotes Consume from
rung 15 to rung 4, which is the branch's largest rank swing — and Soulburst (`1297433`) is a
**Tier-1 registered spell-activation overlay on Consume and Devour** (`fact-classification.md` §4.2), so **Blizzard already
glows it**. That is the same argument that deleted cue E: cap leaves the stock proc glow intact
and does not draw a second mark for a fact the client already marks. The residual is `scenarios.md` §7.5's
misordering 5, and whether a cap-owned virtual row should mirror the client's glow is a
`../render-shelf.md` question, not a catalog one.

**Collapsing Star is gated, and its single readable gate is earned by a structural fact.** A bare
*"clears when castable"* rule would point past rungs 1–4. Rungs **1 and 2 both require a full soul
bank**, and entering Void Metamorphosis **expires** the bank (`sc_demon_hunter.cpp:9179`) with no
way to refill it while transformed — while Collapsing Star exists only inside Meta. So rungs 1–2
are structurally dead for the whole window and need no gate at all. What remains above it is rungs
3–4, and `!proc` is readable. That is the *one secret, many readable gates* fence Havoc puts around
its positive cue, applied here to a row rather than a badge.

⚠ **What clears the gated row is an OPEN FACT and it is load-bearing three ways.** The candidate
read is `C_Spell.IsSpellUsable`'s **first** return. `knowledge/addon-dev/security-taint-and-restricted-data.md`
records a measured trap on it: *"`isUsable` was measured returning **true** for a spell visibly on
cooldown. It answers 'can I afford it', not 'can I cast it'"* — and the measured sample is four
**Fury-gated Havoc spells**, all of them failing on *power*. Collapsing Star has **no cooldown and
no power cost**; its gate is aura-granted access, a third kind of unavailability the sample never
exercised. **Whether `isUsable` goes false without that access is unmeasured, and it must not be
assumed.** Routed as `@verify-ingame`, ClientLab registry id `spell-usable-aura-granted-access`
(§8, item 3 — parked, not `@pending-test`, because no probe exists yet). Its three consumers:
Collapsing Star's hatch, Void Metamorphosis's bank hold, and Voidblade's rung-1 hold. *(The
standing Consume row needs no verdict, so it is not one of them.)*

**The fallback, named now rather than discovered later.** If the read is sealed or answers
uselessly, the hatch is driven instead by a **client-evaluated curve** (V9 / V10 shape): cap hands
the client the sealed availability and a curve, the client writes the result into the hatch's
alpha, and cap never learns the answer. The panel design holds either way; only what clears the
hatch changes. ⚠ One thing to settle *there* rather than here: S2's value-as-alpha trick runs in
the **show-when-non-zero** direction and a hatch needs **hide-when-non-zero**, so the sink and the
curve's polarity are a `../render-shelf.md` question, not a catalog one.

## 8. Open facts, and what ships now

Route as `@verify-ingame` / ClientLab `@pending-test` markers, never guesses. **An open fact
produces no hint until resolved** (`../spec.md` §3.6). **A load-bearing open fact is a
stop-and-ask, and the doctrine is that rows which do not depend on it proceed while the row that
does ships without that hint** — which is exactly how §8.2 is written.

### 8.1 The list

1. **Do the four Devourer overlay auras actually reach `IsSpellOverlayed`?** `fact-classification.md` §4.2 resolves from
   Tier-1 DB2 *which* auras Blizzard registers as icon-highlight overlays. It does not prove the
   read answers true in instanced combat. Candidate-settled by mechanism; confirm before
   shipping any `proc` cue. **Load-bearing on cue D and on the gated virtual row's gate.**
   `@verify-ingame`

## 9. Contract boundary

- **Emphasis uses only readable facts:** `ready` (R2), `affordable` (R1), `identity` (R7),
  `proc`, the trait-config `talent` read, and `aoe` — which is cap's own toggle. The Fury value,
  the soul bank and the harvest counter are **never** read into a Lua condition.
- **Cues carry sealed facts to client-owned sinks:** cue B's colour curve (secret Fury-%) and
  cue C's application count (the soul-bank aura) go straight to a draw call; cap reports
  `offered` / `armed` / `refused` and never reads back.
- **Unknown never becomes confidence,** including through negation — and on a **gated virtual
  row** unknown draws **hatched**, which is the inverted form of the same rule (§6.1). A
  **standing** row asks for no verdict, so it has nothing to be unknown about.
- The catalog declares **no** `power` field (Fury is secret), no `resource` predicate, no
  `sealed-cooldown-range` band (nothing in the branch reads another ability's remaining time),
  no positive cue, no continuous grade, no silence list, no cast sequence, and no vocabulary a
  cue does not use.
